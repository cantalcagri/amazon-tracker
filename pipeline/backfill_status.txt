=== HISTORICAL BACKFILL STATUS (corrected 2026-06-09) ===

Reality check: the earlier version of this file claimed "Phase 2 IN PROGRESS,
4,359 ASINs with full 90-day history, ETA June 9-10". That was wrong — no
process was running a --history pass. The collector loops fetch known ASINs
with history=0, which does NOT backfill historical BSR.

Actual state (2026-06-09):
  • ~453 ASINs have >=30 days of BSR history (from the one-time history=1
    fetches of new ASINs in early June + old CSV imports of the small catalog).
  • The remaining ~4,600 ASINs have BSR only from June 1 onward.

UPDATE 2026-06-10: AUTOMATIC ONE-TIME BACKFILL NOW RUNNING.
  • asin_api_state.history_done tracks which ASINs have had their one-time
    history=1 pass (+5 tok, paid once per ASIN ever). 4,551 queued; 536 that
    already had deep history were stamped done at migration.
  • Each tick upgrades up to KEEPA_HISTORY_PER_TICK (default 25) of its batch
    to history=1, so the backfill completes in ~3-4 sweeps (~1.5-2 weeks)
    without starving per-seller freshness. Raise the env var to finish faster
    at the cost of slower sweeps. Progress check:
      sqlite3 amazon_tracker.db "SELECT history_done, COUNT(*) FROM asin_api_state GROUP BY 1"
  • The daily CSV import (scripts/csv_scheduler.sh) builds BSR history forward
    for ALL ASINs at zero token cost; API daily rows carry BSR via stats=90.
  • Per-seller stock history needs NO backfill — every fetch returns each
    seller's full stockCSV timeline and we keep the 90-day window.
